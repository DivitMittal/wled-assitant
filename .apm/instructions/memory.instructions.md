# MEMORY RULES

## WHERE MEMORY LIVES

| Kind | Location | Edited by hand? |
| --- | --- | --- |
| Durable project knowledge (all agents) | `.apm/instructions/*.instructions.md` | **yes — only here** |
| MCP servers | `apm.yml` → `dependencies.mcp` | yes |
| Claude rules / memory | `.claude/rules/*.md` (APM skips `CLAUDE.md` when rules exist) | no — generated by APM |
| Codex / OpenCode | `AGENTS.md`, `.codex/config.toml`, `opencode.json` | no — generated by APM |
| Claude MCP config | `.mcp.json` | no — generated by APM |
| Scratch notes / session memories | Serena memories (`.serena/memories/`) | via Serena tools; gitignored |

## WHEN TO WRITE MEMORY

Record a fact in the matching `.apm/instructions/*.instructions.md` when it is **durable and non-obvious**:
- a verified behaviour of WLED / arduino-esp32 / ESP-IDF / HyperHDR / Home Assistant that the code depends on (cite file or function);
- a hardware fact (wiring, measured timing, board variant quirk) — mark measured vs. assumed;
- a decision and its reason (e.g. why OE is compile-time, why the RX queue is sized in the constructor);
- a trap that cost time (e.g. CRLF noise in upstream, DTR/RTS reset).

Do **not** record: things obvious from the code, git/jj history, transient task state, secrets, Wi-Fi/MQTT credentials, IPs or MAC addresses of the user's devices.

## HOW TO WRITE MEMORY

1. Pick the narrowest file by `applyTo` (`usermods/**`, build, `tools/**`, else `project-knowledge`). Add a new `<area>.instructions.md` with frontmatter `description` + `applyTo` only when no file fits.
2. Update in place; replace stale facts instead of appending contradictions. Delete facts proven wrong.
3. Keep entries terse (tables/bullets); mark unverified items "(unverified)" and hardware-test results with a date.
4. Regenerate: `apm install && apm compile` (inside `nix develop`, or `uvx --from apm-cli apm …`). Commit the `.apm/` and `apm.yml` changes together with the code change (`jj describe`).
5. If behaviour visible to the user changed, update `README.md` too.
